The files themselves still exist locally and are still read/edited normally — see CLAUDE.md's reading order note. They're mirrored in Notion (Phase 1 page, MVP PRD v1 page) rather than in git.
- **2026-08-20 — Process gap identified: M0.3 skipped:** A repo/Notion status reconciliation surfaced that M0.3 (manual export/import, FR-016), approved unconditionally by DEC-019 (2026-08-19) specifically to gate M1, was never built — M1 shipped in full on 2026-08-19 without it. **Confirmed by Sapna (2026-08-20) as an oversight**, not a reconsideration of DEC-019 or DEC-018 (contrast with the M0.2 gate bypass below, which *was* a deliberate, documented choice). DEC-019 still stands. M0.3 is now owed retroactively and must ship before M2.2 or any later roadmap slice proceeds — see ROADMAP.md M0.3 section and DECISIONS.md DEC-018/DEC-019.
- **2026-08-18 — M0.1 (Installable PWA skeleton):** Added `manifest.json`, `service-worker.js`, `index.html`, and placeholder icons (`icons/`). Deployed to GitHub Pages at https://smahboobani.github.io/adhd-declutter-app/. **Confirmed on-device by Sapna (2026-08-18):** installs via Safari "Add to Home Screen," opens full-screen with no Safari chrome. Slice done.
- **2026-08-18 — M0.2 (localStorage persistence check), in progress:** `index.html` now writes a timestamp to `localStorage` on first load only (never overwritten) and displays "First recorded" / "Viewed just now" / "Days since first recorded" on screen. Verified locally and confirmed on-device on Sapna's actual installed home-screen app (2026-08-18): reopening repeatedly keeps "First recorded" static while "Viewed just now" updates, as expected same-day. Along the way, found and documented a GitHub Pages caching gotcha (see TECHNICAL_DESIGN.md, Deployment/Testing Note) that initially made the update look like it hadn't deployed. **Still needed per ROADMAP.md:** leave the installed app untouched for several real days, reopen, and confirm "First recorded" still shows the original 2026-08-18 timestamp (not reset) — this is a calendar-time test, nothing further to build until then. Do not proceed to M1 (data layer/UI) until this is confirmed.
- **2026-08-18 — M2.1 (Zone-type checklist content, FR-002):** Added `data/zone-types.json` — 22 curated zone types (kitchen junk drawer, bathroom cabinet, closet shelf, entryway/mudroom, bedside table, coffee table, bookshelf, garage shelf, kitchen pantry shelf, bathroom counter, desk/home office surface, linen closet, cutlery drawer, dresser, TV console, pet toy basket, craft shelf, glassware, kitchen appliances, pots and pans, bar, filing cabinet), each with 6-8 typical items, static content only, matches TECHNICAL_DESIGN.md's `ZoneType { id, name, defaultItems[] }` shape. Meets FR-002 acceptance criteria (≥5 items each, static, no AI generation) and covers FR-001's ≥10-zone-type requirement. **Deliberately built out of roadmap order:** FR-002 has no dependencies per PRD.md, so this content-authoring slice doesn't need M1's data layer.
- **2026-08-19 — M1 gate note:** M1 (data layer + zone list) started with the ROADMAP.md M0.2 gate ("do not proceed to M1 until 0.2 is confirmed on-device") formally still open — only same-day on-device confirmation exists as of this date, not the multi-day check the gate calls for. Sapna explicitly chose to proceed anyway when asked. The multi-day persistence check is still outstanding and should be confirmed when enough calendar time has passed; if it fails, the M1 data-layer approach (ADR-3, localStorage) would need to be revisited.
- **2026-08-19 — M1.1 (Data layer):** Added `data.js` — one localStorage JSON blob (`declutter-quest:data`) holding `zones`, `items`, `rewards`, `weeklyCheckins` per TECHNICAL_DESIGN.md's Data Model. CRUD helpers implemented and exercised for Zone (create/read/update/delete) and Item (add/update/delete); `getZonePercentResolved()` added for the list view. Verified locally: create/update/delete confirmed via console, data survives a page reload. Acceptance met.
- **2026-08-19 — M1.2 (Zone list view, FR-011):** Added `app.js` and matching markup in `index.html` — zone list shows name, status, and % resolved per zone; empty state prompts zone creation instead of a blank screen; tapping a zone opens a read-only checklist detail view (full item interaction is M2). Verified locally in-browser: empty state renders with no zones, list renders correctly after creating zones, detail view shows the right items, state survives reload. Acceptance met.
- **2026-08-19 — M1.3 (Zone creation from template library, FR-001):** "Pick from library" flow lists all 22 `data/zone-types.json` types with item counts; selecting one pre-fills the zone name (editable) and creates the zone with its default checklist attached. Verified locally: created a zone from "Kitchen Junk Drawer," confirmed all 8 default items attached and name was editable before creation. Acceptance met.
- **2026-08-19 — M1.4 (Freeform zone creation, FR-003):** "Custom zone" flow prompts for a name only and creates a zone with zero pre-populated items (items addable later via FR-005, which is M2 scope). Verified locally: created a custom zone, confirmed it starts empty with the "No items yet" state. Acceptance met.
- **2026-08-19 — M1.2 fix (duplicate empty-state button):** Caught by Sapna reviewing an interactive preview — the empty-state (FR-011 edge case) had its own `+ New Zone` button in addition to the always-visible header one, so two identical buttons showed together whenever the zone list was empty. Removed the redundant empty-state button (`#new-zone-btn-empty`) in `index.html`/`app.js`; the persistent header button already satisfies the "empty state must prompt zone creation" requirement.
- **2026-08-19 — Service worker cache bump:** Bumped `CACHE_NAME` to `declutter-quest-shell-v3` and added `data.js`, `app.js`, `data/zone-types.json` to the cached shell files so the offline app shell stays in sync with the new M1 code (see TECHNICAL_DESIGN.md Deployment/Testing Note on GitHub Pages cache-control).
